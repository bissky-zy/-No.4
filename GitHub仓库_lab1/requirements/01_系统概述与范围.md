# 系统概述与范围

## 业务背景与问题

校园内闲置书籍的信息目前分散在各班QQ群、微信群和朋友圈中，存在以下问题：

1. **信息不透明**：书籍是否仍可购买、是否已被他人预留，买家需要反复私聊卖家确认。
2. **重复沟通成本高**：卖家发布一条信息后，经常被多人重复询问同一本书是否还在。
3. **取消后状态混乱**：买家预留后又取消，但卖家可能未及时更新信息，导致其他买家白跑一趟。
4. **缺乏集中检索**：买家想找某门课程的教材时，无法跨群搜索，只能靠运气碰。

## 系统目标

设计一个**校园二手书交易平台**（模拟项目，不开发可运行系统），使校园用户能够：

- 集中发布闲置书籍信息
- 按关键词检索可购书籍
- 通过下单操作表达预留意向
- 通过取消操作释放预留

本平台仅解决"信息展示 + 预留登记"问题，不涉及支付、物流等交易环节。

## 服务对象与角色

| 角色 | 说明 | 核心目标 |
|---|---|---|
| 买家 | 想购买二手书的校园用户 | 检索到需要的书并成功预留 |
| 卖家 | 想出售闲置书的校园用户 | 方便地发布书籍信息，让买家看到 |

> 同一用户可以同时承担买家和卖家两种角色。使用预置测试账号登录，账号注册与管理不在本系统范围内。

## 纳入业务（系统范围）

| 编号 | 业务 | 说明 |
|---|---|---|
| B-01 | 发布书籍 | 卖家填写书籍信息并上架，书籍状态默认为"可售" |
| B-02 | 检索与查看 | 买家按关键词搜索书籍，查看书籍详情和当前状态 |
| B-03 | 下单预留 | 买家对"可售"书籍提交预留请求，书籍变为"已预留" |
| B-04 | 取消订单 | 买家取消自己的有效订单，书籍恢复"可售" |

## 排除范围

以下功能**不在本系统范围内**，后续实验也不纳入：

- 真实支付与在线交易
- 退款流程
- 物流配送与取货管理
- 交易完成确认
- 书籍评价与评分
- 个性化推荐
- 用户注册、登录、找回密码等账号管理

## 基本业务约定

| 编号 | 约定内容 |
|---|---|
| B-01 | 一条发布记录代表一本实物书，不支持多本同款合并 |
| B-02 | 下单仅表示"预留"，不表示已付款、已成交 |
| B-03 | 同一本书在同一时刻最多只有一个有效订单（状态为"已预留"） |
| B-04 | 仅订单的买家本人可以取消该订单 |
| B-05 | 取消后订单标记为"已取消"但保留记录，书籍状态恢复为"可售" |
| B-06 | 使用预置测试账号，不做注册和密码找回 |
