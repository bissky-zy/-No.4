# 详细用例描述

> 发布书籍、下单预留、取消订单三个用例的完整字段。用例编号与《02_需求简表》《用例图.png》、FR—UC 对应表一致。
> 版本 v1.2 · 2026-11-13。每条异常分支均注明从哪一步分出、处理结果以及用例继续或结束的位置。

## UC-01 发布书籍（主责：张弋）

| 字段 | 内容 |
| --- | --- |
| 编号 | UC-01 |
| 名称 | 发布书籍 |
| 目标 | 卖家把一本闲置书登记为系统内可检索、可被预留的“可售”书籍。 |
| 主要参与者 | 卖家 |
| 触发条件 | 卖家在“发布书籍”页填写书籍信息后点击“发布”。 |
| 前置条件 | （1）操作者已使用预置测试账号登录；（2）卖家已掌握书名、作者、价格、成色等基本信息。 |
| 成功后置条件 | （1）生成一条状态为“可售”的书籍记录，记录发布者与发布时间；（2）该书出现在检索结果中，可被下单预留。 |
| 失败后保证 | （1）不产生任何“可售”记录，检索结果中查不到该书；（2）已填写的其他字段内容保留，不清空表单；（3）其他书籍的状态不受影响。 |
| 正常流程 | 1. 卖家打开“发布书籍”页，系统显示书名、作者、价格、成色（必填）与描述（选填）输入项。<br>2. 卖家逐项填写书籍信息。<br>3. 卖家点击“发布”，系统校验必填项是否填写、价格是否为合法数值。<br>4. 校验通过，系统生成一条状态为“可售”的书籍记录，并记录发布者与发布时间。<br>5. 系统提示“发布成功”，并在“我发布的书籍”中显示该书。<br>6. 用例结束。 |
| 异常与备选流程 | A1 必填项缺失（第3步分支）：系统指出缺失的具体字段（如“请填写书名”），拒绝提交，不生成记录，保留已填内容。对应 FR-02、NFR-01。<br>A2 价格不合法（第3步分支）：价格非数字、小于等于0或超出暂定范围（1—500元，见 Q-03）时，提示“价格应为1—500之间的数”，不生成记录。对应 FR-02。<br>A3 卖家放弃发布（第2步备选）：关闭页面或返回上一页，不生成记录，草稿不保存（暂定）。对应 Q-01、Q-02。 |
| 关联需求 | FR-01、FR-02；业务规则 BR-01；质量要求 NFR-01；待确认项 Q-01、Q-02、Q-03。 |
| 验收条件 | AC-01-1 给定卖家填写完整信息并提交，则系统生成一条“可售”记录，在检索结果中可查到该书。<br>AC-01-2 给定卖家未填书名直接提交，则提示“请填写书名”，不产生新记录，作者、价格等已填内容保留。<br>AC-01-3 给定卖家填写价格“-5”，则提示价格不合法，不产生新记录。<br>AC-01-4 给定卖家在提交前关闭页面，则系统中不存在该书，也不出现状态为“可售”的空记录。 |

## UC-04 下单预留（主责：易文俊）

| 字段 | 内容 |
| --- | --- |
| 编号 | UC-04 |
| 名称 | 下单预留 |
| 目标 | 买家对一本当前“可售”的书建立唯一的有效预留意向，并得到可确认的结果。 |
| 主要参与者 | 买家 |
| 触发条件 | 买家在书籍详情页或检索结果中选择某本书，点击“下单预留”。 |
| 前置条件 | （1）操作者已使用预置测试账号登录；（2）目标书籍存在且信息完整可显示。说明：“该书此刻是否可售”是系统必须校验、可能被拒绝的条件，因此放在正常流程第3步检查，不写成前置条件。 |
| 成功后置条件 | （1）生成一条状态为“有效”的订单，归属该买家并记录下单时间；（2）书籍状态变为“已预留”；（3）该书此刻只有这一条有效订单。 |
| 失败后保证 | （1）不产生本次请求对应的有效订单；（2）书籍状态与已有有效订单均不改变；（3）用户看到的书籍状态与操作前一致。 |
| 正常流程 | 1. 买家查看某本书的详情，系统显示书名、作者、价格、成色与当前状态。<br>2. 买家点击“下单预留”，系统显示预留说明（下单表示预留，不表示付款）。<br>3. 买家确认，系统检查该书当前是否仍为“可售”。<br>4. 检查通过，系统建立一条“有效”订单，记录买家与下单时间，并把书籍状态置为“已预留”。<br>5. 系统提示“预留成功，请与卖家确认取书方式”，刷新书籍状态显示。<br>6. 用例结束。 |
| 异常与备选流程 | A1 书籍已被他人预留（第3步分支）：系统拒绝，提示“该书已被预留”，不产生新的有效订单，他人订单与书籍状态均不变。对应 FR-06、BR-03。<br>A2 两人几乎同时提交（第3步分支）：以系统检查的先后为准，只有一个请求成功；未成功一方收到与 A1 相同的提示且不产生订单，最终该书仍只有一条有效订单。本次只规定业务结果，不涉及加锁等实现手段。对应 FR-06、BR-03、场景 S-04。<br>A3 同一买家重复点击或网络重试（第2—3步）：该书已因本人上一次成功请求变为“已预留”，第二次请求按 A1 处理；同一买家对同一本书只保留一条有效订单。对应 BR-03。<br>A4 买家下单自己发布的书（第2步备选）：当前暂定不拦截，按正常流程处理，该规则登记为待确认项 Q-05。 |
| 关联需求 | FR-05、FR-06；业务规则 BR-02、BR-03、BR-07；质量要求 NFR-01、NFR-02；待确认项 Q-05。 |
| 验收条件 | AC-04-1 给定书籍X为“可售”，买家甲提交下单，则X变为“已预留”，生成一条归属甲的“有效”订单，并提示预留成功。<br>AC-04-2 给定X已被甲预留，买家乙提交下单，则乙收到“该书已被预留”提示，X仍为“已预留”，甲的订单仍为“有效”，该书有效订单数量仍为1。<br>AC-04-3 给定甲的提交因网络重试再次到达，则系统不产生第二条有效订单，甲最终只看到一条“有效”订单。<br>AC-04-4 给定下单成功，则书籍详情页与检索结果中该书不再显示为“可售”。 |

## UC-05 取消订单（主责：王伟霁）

| 字段 | 内容 |
| --- | --- |
| 编号 | UC-05 |
| 名称 | 取消订单 |
| 目标 | 买家撤销本人已提交的有效预留，使该书重新可供他人下单，同时保留可追溯的历史记录。 |
| 主要参与者 | 买家 |
| 触发条件 | 买家在“我的订单”中选择一条状态为“有效”的订单，点击“取消订单”。 |
| 前置条件 | （1）操作者已使用预置测试账号登录；（2）被选订单存在，其书籍信息完整可显示。说明：“操作者是订单买家本人”“订单仍为有效”属于系统必须校验、可能被拒绝的条件，故写在正常流程第3步，不写成前置条件——否则越权取消与重复取消将没有可检查的处理结果。 |
| 成功后置条件 | （1）该订单状态变为“已取消”并记录取消时间，仍保留在历史订单中；（2）对应书籍状态恢复为“可售”，重新出现在检索结果中；（3）该书此刻没有其他有效订单，任何买家（含原买家）均可重新下单。 |
| 失败后保证 | （1）订单状态、书籍状态、订单归属均不发生任何变化；（2）不产生新的订单，也不产生任何状态变更记录；（3）若该书当前已有他人的有效订单，该订单及其预留状态不受影响。 |
| 正常流程 | 1. 买家进入“我的订单”，系统列出本人的订单，显示书籍名称、下单时间与当前状态。<br>2. 买家选择一条“有效”订单并点击“取消订单”，系统显示书名与取消影响说明（取消后该书恢复可售、订单保留在历史记录中），请买家确认。<br>3. 买家确认取消，系统校验操作者是否为该订单的买家本人，以及订单当前是否仍为“有效”。<br>4. 两项校验通过，系统把订单状态置为“已取消”，并记录取消时间与操作者。<br>5. 系统把对应书籍状态恢复为“可售”，同步更新书籍详情页与检索结果中的状态显示。<br>6. 系统提示“取消成功，该书已恢复可售”，刷新订单列表，该订单移入历史订单。<br>7. 用例结束。 |
| 异常与备选流程 | A1 越权取消（第3步分支）：操作者不是该订单的买家本人。系统拒绝，提示“只能取消本人的订单”并返回订单列表；订单状态、书籍状态与订单归属均不改变。对应 FR-09、BR-04。<br>A2 重复取消（第3步分支）：订单当前已是“已取消”。系统提示“该订单已取消”，不再执行状态变更，并保持该书当前状态不变；若该书已被他人重新下单，新订单不受影响。对应 BR-06、BR-07。<br>A3 买家放弃取消（第2步备选）：在确认页选择返回或关闭，不产生任何状态变更，订单保持“有效”，书籍保持“已预留”。<br>A4 取消成功后的旧请求再次到达（第3步分支）：同一订单的取消请求因网络重试或重复点击再次到达时，系统按订单标识定位到该订单，发现其已为“已取消”，按 A2 处理；处理时不得依据请求中携带的书籍信息改写书籍状态，因此即使该书已产生新订单，新订单仍然有效。对应 BR-07、场景 S-05。 |
| 关联需求 | FR-07、FR-08、FR-09；业务规则 BR-04、BR-05、BR-06、BR-07、BR-08；质量要求 NFR-01、NFR-03；待确认项 Q-06、Q-07。 |
| 验收条件 | AC-05-1 给定买家甲有一条有效订单O1（书籍X为“已预留”），当甲确认取消O1，则O1状态为“已取消”并保留在历史订单中，X状态为“可售”并重新出现在检索结果中。<br>AC-05-2 给定买家乙（非订单买家）对甲的有效订单O1发起取消，则系统提示“只能取消本人的订单”，O1仍为“有效”，X仍为“已预留”，取消时间为空。<br>AC-05-3 给定订单O1已取消、书籍X已被买家丙重新下单形成有效订单O2，当O1的取消请求再次到达，则系统提示“该订单已取消”，O2仍为“有效”，X仍为“已预留”，O1的取消时间不被改写。<br>AC-05-4 给定买家甲在确认页放弃取消，则O1仍为“有效”，X仍为“已预留”，历史订单中不新增记录。<br>AC-05-5 给定取消成功，则该书立即从甲的有效订单列表移入历史订单，书籍详情页显示“可售”，且提示文字与状态一致。 |
