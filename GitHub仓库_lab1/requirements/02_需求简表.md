# 需求简表

> 编号规则：功能需求以 FR-XX 编号，非功能需求以 NFR-XX 编号，后续实验沿用。

## 功能需求（FR）

| 编号 | 需求描述 | 来源与依据 | 优先级 | 验收条件或检查方法 |
|---|---|---|---|---|
| FR-01 | 卖家可填写书名、作者、价格、书籍成色和书籍描述，提交后发布一本二手书，书籍状态默认为"可售" | 场景S-01（小林发布闲置教材） | 高 | 给定卖家已登录，填写完整信息后点击发布，书籍出现在系统可售列表中，状态显示为"可售" |
| FR-02 | 发布书籍时，书名、作者、价格、成色为必填项；若任一必填项为空，系统拒绝提交并明确指出缺失项，同时保留用户已填写的内容 | 场景S-01（缺失信息时应得到什么反馈） | 高 | 给定卖家不填写书名直接提交，系统提示"请填写书名"，其他已填字段内容保留不丢失 |
| FR-03 | 买家可输入关键词检索书籍，系统返回书名包含该关键词的所有可售书籍列表 | 场景S-02（小周想找到某门课程需要的书） | 高 | 给定系统中有3本可售书籍，买家输入关键词"数据结构"，返回所有书名包含"数据结构"的书籍 |
| FR-04 | 买家可点击查看某本书的详情页面，显示书名、作者、价格、成色、描述以及当前销售状态（可售/已预留） | 场景S-02（查看结果时需要知道什么） | 高 | 给定一本可售书籍和一本已预留书籍，买家分别查看详情，可售书籍标注"可售"，已预留书籍标注"已预留" |
| FR-05 | 买家可对状态为"可售"的书籍提交下单预留请求；下单成功后书籍状态变为"已预留"，系统生成一条有效订单并提示下单成功 | 场景S-03（小周选中可售书籍并提交预留） | 高 | 给定一本状态为"可售"的书籍，买家点击下单，系统提示"预留成功"，书籍状态变为"已预留" |
| FR-06 | 当书籍状态为"已预留"时，其他买家对该书的下单请求应被系统拒绝，并提示"该书已被预留"，不产生新的有效订单，原订单不受影响 | 场景S-04（小周和小陈几乎同时预留同一本书） | 高 | 给定书籍已被买家A预留，买家B对同一书籍提交下单，系统拒绝并提示"该书已被预留"，买家A的订单保持有效 |
| FR-07 | 买家可在"我的订单"中查看自己的有效订单，并对状态为"有效"的订单执行取消操作 | 场景S-05（小周取消自己的订单） | 高 | 给定买家有一条状态为"有效"的订单，买家点击取消，订单状态变为"已取消" |
| FR-08 | 订单取消后，对应书籍的状态恢复为"可售"，其他买家可以对该书下单；被取消的订单记录仍然保留在历史订单中 | 场景S-05（小周取消后小陈重新下单） | 高 | 给定买家A取消了书籍X的有效订单，买家B随后对书籍X下单，下单成功；买家A的已取消订单仍可在历史记录中查看 |
| FR-09 | 仅订单的买家本人可以取消该订单；当非订单买家尝试取消他人订单时，系统应拒绝并提示"无权取消他人订单"，订单和书籍状态均不改变 | 场景S-06（小陈尝试取消小周的订单） | 中 | 给定买家A的有效订单，买家B尝试取消该订单，系统提示"无权取消他人订单"，订单仍为"有效"，书籍仍为"已预留" |

## 非功能需求（NFR）

| 编号 | 需求描述 | 来源与依据 | 优先级 | 验收条件或检查方法 |
|---|---|---|---|---|
| NFR-01 | 必填信息缺失时，系统必须**明确指出具体缺失项的名称**（如"请填写书名"），而不是笼统提示"信息不完整"；同时必须保留用户已填写的其他内容 | 从FR-02延伸的可检查质量要求；任务单要求"提示友好"可细化为可检查条件 | 高 | 逐项遗漏每个必填字段并提交，观察系统是否逐一指出缺失项名称，且已填内容不丢失 |
| NFR-02 | 在正常网络条件下，下单和取消操作的响应时间不超过3秒（从用户点击操作到系统返回结果） | 任务单要求非功能需求"可检查"；预留操作需要快速反馈避免用户重复点击 | 中 | 模拟正常网络环境，对可售书籍执行下单和取消操作，测量从提交到收到结果的时间，均不超过3秒 |
| NFR-03 | 需求简表中的FR编号、用例图中的UC编号、用例描述中的关联需求三者必须保持一致，命名和编号不矛盾；任何修改必须同步更新三处 | 指导书要求"跨材料一致性"；防止需求文档、用例图和详细描述出现脱节 | 高 | 交叉核对：随机抽取3条FR，确认在用例图和用例对应表中都能找到对应的UC，且名称描述一致无矛盾 |
